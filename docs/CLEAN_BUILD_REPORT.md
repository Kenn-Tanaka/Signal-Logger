# クリーンビルド検証結果

## 結論

配布用Builder ZIPを新しい一時ディレクトリへ展開し、依存ソース取得からバイナリZIP生成まで成功しました。
既存の `.deps/`、`3rdparty/`、`build/`、実測データは使用していません。
ただし、ホストのWindowsと既存コンパイラ等を使用しています。新規Windows VMでの検証ではありません。

## 検証で修正した問題

- wxWidgetsのsubmodule未取得を修正。
- wxWidgetsが生成するRelease／Debug設定ヘッダから、Release側を明示選択。
- 日本語SUBST出力の文字化けを避け、Unicode Windows APIでドライブの実体を解決。
- ライセンスファイル1個によるソース検証とvendorフォールバックを廃止。
- 公式ライセンス原文の収集先を実際の固定ソースに合わせ、ランタイム通知をハッシュ固定。
- 旧インストールをミラー上書きせず、完成セットへ切り替えて旧セットを退避。
- ビルド時の来歴・ソース／EXEハッシュと配布物を照合。テスト0件を失敗に変更。
- 実機録音試験を明示指定の別CTestに分離。
- バイナリ用READMEとビルダー用手順を分離。

初期の試行は設定ヘッダ選択で失敗しました。修正後は新しいBuilder ZIPを新規ディレクトリへ展開し直して検証しています。

## 範囲外・残存事項

前回レビューの再生ファイル切替競合、メタデータ識別不足、欠落警告の保持など、アプリ本体の残存指摘は今回修正していません。
この結果は機能全体のリリース承認ではありません。
新規Windows VM、別PC、8ch長時間記録、ストレージ停止・電源断・USB抜去は未検証です。
既存のルートEXE・依存物・配布ZIPは上書きしていません。新しい実行ファイルは検証済みバイナリZIPを使用してください。
検証用の依存ソース・ビルド・ログは一時ディレクトリに保持しています。グローバルなツール導入・設定変更・Git commitは行っていません。
